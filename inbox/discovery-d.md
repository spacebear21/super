The most useful precedent is Elements PSET's explicit fee output: the fee is a signed transaction output rather than a number inferred from untrusted peer input amounts, while consensus Pedersen balance rejects inflated inputs, so the sender never has to authenticate a peer's amount to know what it pays. The Bitcoin implementations confirm the trade-off the maintainer identified, since rust-bitcoin trusts witness UTXOs outright, BDK requires previous transactions by default with a trust_witness_utxo opt-out, and bitcoinjs-lib and BDK now at least reject inconsistent dual-UTXO inputs, but none of them solves the witness-only segwit case without the previous transaction.
